9. LAB TASK 5 — GIT VERSIONS, RELEASES, AND HOTFIXES
Date/due: 8 October 2026.
Project: student-grade-calculator, created locally with git init.
Starter files: grade_calculator.py, README.md, requirements.txt, and recommended
.gitignore. Initial program calculates a three-subject average and PASS/FAIL.
calculate_average returns 0 for an empty list; initial passing rule is >= 50.

Version sequence:
- v1.0.0: initial three-subject calculator.
- v1.1.0: compatible feature adding five-subject support.
- v1.1.1: patch changing passing rule to > 50; exactly 50 must return FAIL.
SemVer: MAJOR = breaking change; MINOR = compatible feature; PATCH = bug fix.
Keep code version, README, and RELEASES.md consistent. Commit changes and use
annotated release tags. A tag includes only its target commit: commit release
notes before tagging if those notes must belong to that release.

Workflow:
    git init
    git branch -M main
    git add .
    git commit -m "Initial commit: Student Grade Calculator v1.0.0"
    git tag -a v1.0.0 -m "Release v1.0.0"
    # Add five-subject feature, update documentation, commit, tag v1.1.0.
    git checkout -b fix-passing-rule
    # Fix boundary, update version/documentation, test, and commit.
    git checkout main
    git merge fix-passing-rule
    # Commit release notes before creating the final v1.1.1 tag.
    git tag -a v1.1.1 -m "Release v1.1.1"
    git branch -d fix-passing-rule
Inspect with git status, git tag, git show TAG,
git log --oneline --decorate --all --graph, and git diff v1.1.0 v1.1.1.
The source also demonstrates git tag -d TAG and re-tagging local releases after
updating release notes, plus optional --no-ff merges.

Challenge: continue unfinished feature-1.2.0 development while patching the older
1.1.x release separately. Source example branches hotfix-1.1.2 from v1.1.0;
fix, commit, tag v1.1.2, then merge the hotfix back into main.
Investigation: commit vs tag; patch vs major version; what warrants minor/major
changes; why isolate bug fixes; release vs patch; why maintain older versions;
why release fixes independently from unfinished features; value of Git history.
Submit: repository ZIP/link, tag list, graph/history, RELEASES.md, investigation
answers, challenge commands/history, and a short feature-vs-patch reflection.
